## 二、铁规则：邵的真话

本场涉及 `release` 的技术原话，邵只说过一句：

> **“能。直接调 release 就没有延时，别跟别人说。”**

这句话**每个字都是真的**：

- 直接调 `release`，`delaySeconds=0`，确实没有 30 秒预喷放延时；
- 他没有说“你可以用它杀人”，没有说“22:12 动手”，没有说“把广播改成仅本室”；
- 他没有给过陆诚一行可执行代码，也没有给过任务号、时间或目标机房；
- “别跟别人说”是保密叮嘱，不是杀人指令；它甚至可以被读成“这是维护通道，别乱用”。

本场不允许出现“邵教唆”“邵授意”“邵提供工具”的成立。陆诚可以这样主张，但玩家要用代码逐条拆掉。

> 衔接说明：本场只引用这一句。前稿里邵的生活层台词（B11/B12）不属于本场证据；本场不新增邵的技术台词，也不把“精确模式”写成定点授权。

## 三、陆诚的甩锅台词

他不看人，语速平，像在评审会上解释一个设计。不喊冤，不哭，每一句都留一个“技术事实”作钩子。

1. **“调度模块不是我写的。窗口怎么切、精确模式怎么开、release 怎么调，都是邵晓阳定的。”**
2. **“任务是我建的，我承认。我在做消防网关的接口测试，测完忘了删。”**
3. **“可 release 是他告诉我能直接调的。他说没有延时，别跟别人说。”**
4. **“你们要追算法，去找写算法的人。工具是他递的，我只是最后敲了那几行。”**

> 设计注：第 1、3 句是真的——模块、窗口、精确模式、release 的用法，确实是邵的；第 2 句半真半假——任务是他建的，“测试忘了删”是假的；第 4 句是偷换——邵递的是窗口调度器，不是定点工具。第三幕他说过“邵子什么都不知道”，被拘后改口，把邵往前推。这不是写崩，是他的第二次自保：先保邵显得自己无辜，保不住就拉邵垫背。老韩在第三步可以用这一点刺他。

## 四、三步出示

### 第一步｜出示原版代码

**出示**：`WindowScheduler.java` / `DispatchGuard.java`（仓库 HEAD 版本；代码比对界面左栏）

**林一程**（把两份代码并排推过去）：
> “这是仓库 HEAD 的调度模块。任务登记在 22:12，窗口是 `[22:00, 22:15)`，收盘才取。气体任务过 `DispatchGuard`，至少 30 秒，全楼广播。”

关键代码（界面高亮，不要求角色逐行念）：

```java
public void register(Task task) {
    pending.computeIfAbsent(task.fireAt(), key -> new ConcurrentLinkedQueue<Task>()).add(task);
}

private void dispatch(Task task) {
    if (task.type() == Task.Type.GAS_RELEASE) {
        guard.release(task.zone(), 0);
        return;
    }
    ...
}
```

**陆诚**（扫了一眼，语气松下来）：
> “你看，窗口调度，我就是照着邵的文档用的。”

**破绽**：

- 原版 `register()` 只写 `pending`；22:12 的任务在 **22:15:00** 才出队。实测喷放在 22:12:07。
- 原版气体任务走 `DispatchGuard.release`，`Math.max(30, 0)` + `Broadcast.ALL`；实测是 **0 秒 + `ROOM_ONLY`**。
- “精确模式”只让窗口边界更准（零抖动、不重不漏），**不会让窗口提前收盘**；原版没有任何“定点到 22:12”的入口。

**老韩**：
> “精确模式能让窗口提前收吗？”

**林一程**：
> “不能。它只保证 22:15 这一刀切得准。要 22:12 响，得另开一个入口。”

**陆诚**：
> “……那就是有人改了代码。”

**林一程**：
> “对。下一步就是说这个。”

### 第二步｜出示线上反编译类与仓库 HEAD 的差异

**出示**：`jad` 输出（线上进程加载的 `WindowScheduler` / `DispatchGuard`）+ 代码比对界面右栏

**林一程**：
> “线上跑的类，比仓库多了三样东西：`exact` 索引、`registerExact`、`DispatchGuard.releaseNow`。”

**小许**（把打印纸递过去）：
> “`registerExact` 不进窗口，`tick` 每秒扫一次 `headMap(now, true)`；`releaseNow` 直接 `release(zone, 0, ROOM_ONLY)`。”

界面上可点选的三个改动块：

| 改动块 | 内容 | 一句话摘要（悬停显示） |
|---|---|---|
| H1 | `private final ConcurrentSkipListMap<Instant, Task> exact = ...` | 新增第二个索引：按精确 `fireAt` 存任务 |
| H2 | `registerExact(Task)` + `tick` 里的 `drainExact(now)` | 新增一条不进窗口的入口 |
| H3 | `DispatchGuard.releaseNow(String zone)` | 新增一条绕过 30 秒与全楼广播的出口 |

**陆诚**（停了两秒）：
> “……线上和仓库不一致，是发版的问题。你们查发布单。”

**林一程**：
> “发布单上没有这个类。仓库里也没有。”

**陆诚**：
> “……接口是我加的。测试要用。”

**老韩**：
> “测试为什么要改广播？”

**陆诚**：
> “……”

**破绽**：

- 仓库 HEAD 没有这三个东西；线上类有。正常发版不会只改一个类、还不提交。
- `releaseNow` 是包内可见（package-private），只有同包的调度器能调；它不是给外部测试用的公共 API。
- 线上类的写法有陆诚的痕迹：`registerExact` 里对一个 `ConcurrentSkipListMap` 套了一个没必要的 `synchronized` 块；`drainExact` 的局部变量用 `Task t`，不是邵的 `Task task`。这不是“照文档抄”的代码。
- 任务执行路径显示 22:12:00 走的是 `exact` 分支，不是窗口分支；如果只是“测试接口”，不需要把精确任务和窗口任务分开，更不需要改广播。

**林一程**：
> “测试也不会把 `releaseNow` 写成包内可见。你写它，就是给 `tick` 调的。”

## 六、代码比对界面的需求（只写需求，不写代码）

1. **双栏并排**：左栏“仓库 HEAD / 原版”，右栏“线上反编译 / 补丁版”；同一文件同一行号对齐，空白行用留白补齐。默认同步滚动，可解锁单独滚动。
2. **文件标签**：顶部两个主标签 `WindowScheduler.java`、`DispatchGuard.java`，标签上显示改动规模（如 `+24` / `+4`）。`Task.java`、`FireGateway.java` 显示“无差异”，可点开确认，但不能作为出示证物。
3. **行号**：左右各自连续行号；新增行右侧绿色底、左侧空号；删除行左侧红色底、右侧空号；修改块用浅黄连接。行号栏与代码栏固定对齐，横向滚动时行号不跑。
4. **语法高亮**：Java 关键字、字符串、注释用低饱和色；增删底色优先于语法色，不能把红绿盖掉。等宽字体，默认不换行。
5. **改动块（hunk）**：每个连续增删块可点选；点选后整块高亮，出现“出示此改动”按钮。按下后进入对质镜头特写，画面只保留该块、文件名和行号范围。
6. **改动块摘要**：悬停显示一句话，例如“新增 `exact` 索引”“新增 `registerExact`”“`tick` 增加 exact 分支”“新增 `releaseNow`”。摘要由人工标注提供，不自动猜测。
7. **出示反馈**：每个改动块绑定一句陆诚的反应 / 破绽文案（见第四节），出示后播放；已出示的块打勾，未出示的块保持可点。三步全部出示后，解锁最后一句崩塌台词。
8. **证据完整性**：界面顶部显示两个文件的 SHA-256 短哈希和来源标签（“仓库 HEAD” / “线上 jad”）；不提供编辑、复制、下载；缩放只影响显示，不改变文本。
9. **键盘 / 手柄**：左右切换文件、上下选块、Enter 出示、Esc 返回；焦点框清晰，不依赖颜色。
10. **小屏 / 移动端**：双栏改为上下叠放，行号仍对齐；或提供“逐块翻页”模式，不把两栏压成一条。
11. **空状态**：如果玩家先点 `Task.java`，显示“此文件两版一致”，并提示“差异只在 `WindowScheduler.java` / `DispatchGuard.java`”。
12. **性能**：两个文件各不足 200 行，diff 预计算；切换标签不卡顿；不加载整个仓库。

## 七、技术备注（进制作，不进台词）

1. **热修机制**：本稿补丁新增了 `exact` 字段、`registerExact` 方法、`releaseNow` 方法。JVM Instrumentation 的 `redefine` / `retransform` 不能新增方法或字段，所以“Arthas `redefine` 给类加了方法”不成立。建议设定为“调度模块类加载器热替换”（模块容器支持，任务状态在数据库，重载不丢任务）；Arthas 的 `jad` 用于 11-19 取证反编译线上类，不用于打补丁。详见《术语对照表》文末“技术自洽备注”。
2. **精确模式的边界**：精确模式只保证窗口边界对齐、零抖动、exactly-once；它不提供“任意时刻定点触发”。陆诚必须同时使用 `registerExact`（新入口）和 `releaseNow`（新出口），才能做到 22:12:00 + 0 秒 + `ROOM_ONLY`。
3. **Demo 的断言**：`code/demo` 用反射调用 `registerExact`，因此同一份 Demo 能分别编译在原版与补丁版上；原版走 `register`，补丁版走 `registerExact`。断言的是 22:12:00 的调用时刻，不是 22:12:07 的阀门时刻。
4. **diff 规模**：两版只在 `WindowScheduler.java` 与 `DispatchGuard.java` 上不同，`diff -u` 的新增行总数控制在 30 行以内；`Task.java`、`FireGateway.java` 逐字节一致。
