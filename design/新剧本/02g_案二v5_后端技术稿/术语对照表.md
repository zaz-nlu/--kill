## 二、调度与定时任务

| 稿中说法 | 真实术语 / 实现 | 游戏里怎么用 | 状态 |
|---|---|---|---|
| 调度模块 / 时间窗 / 收盘 tick | 自研批量调度器：按 15 分钟窗口聚合任务，窗口 `[start, end)` 左闭右开，边界对齐整刻（:00、:15、:30、:45）；收盘 tick 把整个窗口的任务一次取走。它不是 cron，也不是“到点触发”的闹钟。 | 原版 22:12 的任务在 **22:15:00** 才执行；这是邵的原版设计，也是“算法不能定点杀人”的核心。`registerExact` 是陆诚另加的第二个入口，不是原模块的能力。 | 代码即设定 |
| 精确模式 | 本稿自定义术语：窗口边界对齐整刻、jitter=0、exactly-once（不重不漏）。它让“窗口收盘”这一刀切得更准，**不提供任意时刻定点触发**。 | 苏闻信里的“精确模式，文档里没有”指的是这个开关；陆诚把它曲解成“可以精确到 22:12”，实际他必须另加 `registerExact` 和 `releaseNow` 才能做到。 | 本稿自定义；不要和 NTP/PTP 的“精确时钟”混为一谈 |
| 定时任务（Quartz / Spring `@Scheduled`） | Quartz：`JobDetail` + `Trigger`（`CronTrigger` / `SimpleTrigger`），持久化时有 misfire 策略；Spring `@Scheduled`：`fixedRate` / `fixedDelay` / `cron`，进程内调度，重启后不保留错过的触发（除非自己持久化）。 | 如果玩家问“为什么不用 Quartz”：这是设备批量下发模块，窗口聚合是业务需求；Quartz 的 misfire 补偿反而会“补跑”，不符合“窗口收盘一次取走”的语义。陆诚的 `registerExact` 是绕过窗口，不是换 Quartz。 | API 名称准确；具体版本行为待核 |
| misfire | 错过触发后的补偿策略。Quartz 常见取值：`MISFIRE_INSTRUCTION_SMART_POLICY`、`MISFIRE_INSTRUCTION_FIRE_ONCE_NOW`、`MISFIRE_INSTRUCTION_DO_NOTHING`、`MISFIRE_INSTRUCTION_IGNORE_MISFIRE_POLICY`。 | 可用来解释“原版为什么不会在 22:12 补触发”：窗口调度不是 misfire 补偿；错过收盘就等下一个窗口或不补。**不要写成“精确模式会补跑”**。 | 准确 |

## 六、待核清单（不要写进角色台词）

- MySQL `ALTER DATABASE ... READ ONLY` 的版本/分支支持情况。
- 公司实际启用的是哪种审计插件；是否开了 `general_log`（建议设定为**没开**）。
- 消防主机、协议网关的厂商、型号、寄存器地址、广播分区配置名。
- 30 秒预喷放延时的规范依据（不同规范/地区可能不同）。
- CFR 的版本、输出格式，以及对 Java 8 字节码的支持情况。
- 部署目录、systemd unit 名、`auth.log` / `secure` 的实际路径（Debian/Ubuntu 与 RHEL/CentOS 不同）。
- Maven 版本与 `Built-By` 的生成/覆盖方式。
- 项目的构建工具与产物路径（Maven `target/` / Gradle `build/`）。

## 七、给台词的约束

1. 角色嘴里不要出现未核实的厂商型号、寄存器地址、错误码细节；用“网关日志”“后台任务详情”“类文件哈希”这类可验证的说法。
2. 邵关于 `release` 的技术原话只有一句：“能。直接调 release 就没有延时，别跟别人说。”这句话字面为真；不要让他说出“精确模式可以定点”这种假话。
3. 陆诚可以说“精确模式是邵教的”，但不能说“邵让我 22:12 喷放”。前者是技术事实，后者是栽赃。
4. 陆诚可以说“工具是他递的”，但代码比对要能拆掉：邵递的是窗口调度器，不是定点工具；`registerExact` 和 `releaseNow` 是陆诚加的。
