# 章节化设计（四案 = 四个独立章节）

> 2026-10-30。用户定：**每章独立**，参考《逆转裁判》的成熟结构；**"回溯"也要按章节分**。
> 本稿是设计，不含代码。下一步见第八节。

---

## 一、参考《逆转裁判》借什么

| 逆转裁判 | 本作怎么用 |
|---|---|
| 一话就是一个完整的案子：标题卡、序章、结案卡 | 每案一个 Chapter：标题卡（"案二·苏闻"）→ 序章 → 正文 → 结局卡 |
| 调查篇 → 法庭篇，两段交替 | 已经有：**调查日**（现在的"第 N 天"）→ **终章对质**（现在的 finale 四幕）。章节里把这两段显式命名为"调查篇 / 对质篇" |
| 每话重新发法庭记录，证物不带到下一话 | **每章证物、证言、笔记、结论卡全部从零开始**；ID 加案号前缀，永不冲突 |
| 人物档案跨话累积 | 只有"人物档案"和"通关记录"跨章（见第三节） |
| 第一话是教学，后面每话引入一个新机制 | 案一教学；案二引入"时间戳"推理；案三一夜黑案；案四总推理 + boss 战 |
| 通关后有章节选择，每话独立可重玩 | 标题页接"章节选择"：未解锁 / 可玩 / 已通关（显示最佳结局） |
| 失败 → 回到上一个检查点重来 | 现有"回溯树"正好承担检查点，按章保存 |

## 二、章节是什么（ChapterDef）

每章一份定义，数据放 `src/data/chapters/<id>/`，案一的现有文件保持原位，先由一份 `c1` 定义指过去。

```
id            c1 | c2 | c3 | c4
title/sub     "案一·熄灯" / "9 月 15 日起"
order         1..4
unlock        上一章通关（见第六节）
calendar      每天：{ label: "第 1 天", date: "9 月 15 日", startHour, lastHour, fixedEvents }
prologue      序章场景 id
trial         对质篇入口：{ scene, firstExam }          （案一 = finale_intro / finale_act1）
lastDay       最后一个调查日（案一 5，案二 3）
startState    { hour, money, hp, trust, affinity{...}, intel[...] }   本章自己的开局数字，不继承
startKit      { evidence[], testimony[] }                          本章开局发的"卷宗"（见第三节）
endings       { id → {title, text, clears: bool} }                 clears = 算不算通关（BAD 不算）
mechanics     { danger, shop, gifts }                              案一有危险与袭击，案二按需
```

## 三、章节之间带什么、不带什么

**不带**：数值（好感、信任、金钱、生命）、证物、证言、笔记、flag、回溯树。每章开局数字由本章 `startState` 决定，可单独测试，可从章节选择直接进。

**带（只有三样，都是只读的）**：
1. **通关记录**：每章通关了没有、最佳结局是什么（章节选择页用）。
2. **人物档案**：像逆转裁判的"人物"页，随章节解锁；每章结算时新增该章出场人物的一条（外貌、身份、关系、一句话备注）。只增不改，不影响玩法。
3. **正史前提**：后面的章节假设前面是"正史"（案一的 TRUE END：贺川行政处罚、郑岑停职后复职、苏闻留职察看）。不管玩家打出哪个结局，案二的序章开头用一段叙述交代这些前提。这样每章内容写死一种世界状态，不用为四种结局各写一遍。

**需要带到后面章节的证物，怎么办**：不跨章引用 ID，而是在新章开局的 `startKit` 里**重新发一份本章自己的卷宗条目**。
- 例：案四的 `startKit` 里有"贝塔之星（案一卷宗）""六局棋谱（案三卷宗）""苏闻的信（案二卷宗）"，ID 是 `4E..`，说明里写来历。
- 好处：每章数据自给自足；从章节选择直接玩案四也不缺东西；不会出现"玩家没拿到案一的 E23 却在案四要用"。

## 三点五、章节流程（状态机）

```
标题 → 章节选择 → 标题卡 → 序章 → 调查日（每天：行动菜单 / 夜晚推理）→ 对质篇（幕）→ 结局卡 → 章节选择
```
- 新增两个 screen：`chapters`（章节选择）、`card`（标题卡 / 结局卡）。
- 结局卡显示本章结局名；若 `clears` 为真，写入通关记录并解锁下一章。
- 章与章之间的过场（案二到案三只隔 8 天，案三到案四隔三个月）写成**下一章的序章**，不是上一章的结尾。

## 四、"回溯"按章节分

现状：一棵全局树，存在 `localStorage['jiudian-timeline']`；节点只记 `day / hour`；`TimelinePanel` 按"序章 / 第 N 天（9 月 14+N 日）"分组，日期写死。

新设计：

| 项 | 做法 |
|---|---|
| 存储 | 每章一棵树：`jiudian-timeline:<chapterId>`；旧 key 自动迁成 `c1` |
| 节点 | 增加 `chapter` 字段；节点的 `state` 里也带 `chapter` |
| 分组 | 面板标题从该章 `calendar` 读：`第 1 天 · 9 月 15 日`，序章与"对质篇"各成一组；不再写死日期 |
| 范围 | 游戏内的"回溯"只显示**当前章**的树，不能跨章；回到别的章的节点要走章节选择 |
| 章节选择页 | 每章一张卡：状态、最佳结局、最后进度（"第 3 天 14:00"）、[继续] [重新开始] |
| "序章"节点 | `rewindTo` 里 `kind==='start'` 播的场景由写死的 `prologue` 改成该章 `prologue` |

## 五、存档按章节分

| 现状 | 新 |
|---|---|
| `jiudian-auto` / `jiudian-save` / `jiudian-save-N`，版本固定 1 | `jiudian-auto:<chapterId>`、`jiudian-save:<chapterId>:<N>`；`SAVE_VERSION = 2`，`state.chapter` 必填 |
| meta 只有 day/hour | meta 加 `chapter`、日期文案、结局（若已通关） |
| 读档 | 存档面板列出**全部章节**的存档，按章分组；读取别章存档会直接切章 |
| 旧存档 | 版本 1 视为 `c1`，自动迁移，不丢 |

标题页的"继续"= 全部章节里最近一次的自动存档。

### 五点五、存档要明确告诉玩家"这是哪一章的存档"（用户 10-30 补充）

| 场合 | 提示 |
|---|---|
| **存档面板**（游戏内） | 顶部固定一行：`当前章节：案二·苏闻　存档只在本章内有效`；每个槽位都带章节标签（`案二 · 第 2 天 14:00`），空槽写`本章空槽`。别章的存档单独折叠成"其他章节的存档"，灰色、只读展示，点开才能读 |
| **读档面板** | 按章节分组：案一 / 案二 / …，组头显示该章状态（未解锁 / 进行中 / 已通关）。读取别章存档前弹确认：`这是【案一·熄灯】的存档，读取后将离开当前的【案二·苏闻】。当前进度会自动保存。` [读取] [取消] |
| **章节选择页** | 每章卡片显示该章**自动存档**的时间、进度和结局（`第 3 天 14:00 · 上次游玩 10-30 18:20`）；点 [重新开始] 会提示：`重新开始会清空本章的自动存档与回溯记录，手动存档槽不受影响。` |
| **首次进入第二章时**（一次性提示卡，不再出现） | `从本章起，存档与回溯按章节分开保存。随时可以在章节选择里回到之前的章节，它们的存档不会被覆盖。` |
| **自动存档** | 切章、通关、返回标题时，对当前章做一次自动存档，并在右下角小提示：`已自动保存（案二·第 2 天）` |
| **旧存档迁移** | 第一次打开新版本时，若检测到旧存档，提示一次：`已把你之前的存档归入【案一·熄灯】。` |
| **回溯面板** | 标题同样写明本章：`回溯 · 案二·苏闻`，并注一句：`这里只显示本章的选择，其他章节在章节选择里回溯。` |
| **删除存档** | 删除前提示章节名和进度，防止误删别章存档 |

**数据上的保证**：存档文件名与 meta 都带 `chapter`，读档时若 `state.chapter` 与槽位不符直接拒绝并报错，不静默覆盖。

## 六、解锁规则（推荐）

- **任意"通关型结局"解锁下一章**：案一的 TRUE / A / B / C / 隐藏 都算；BAD 1/2/3 不算（玩家死了、被批捕、被迫辞职，这是失败）。
- 通关后可重玩，通关记录只记最佳结局。
- 案一 TRUE END 额外给一个"完美"标记，不影响解锁，只在章节卡上显示。

## 十、前情提要（Previously on…）

像美剧每集开头那种"前情提要"：从**案二起**，每章开始前播放一段，**可跳过，可在章节选择页和游戏内菜单里重看**。案一没有。

**形式**：3 到 6 张文字卡，每张一个短标题 + 2 到 3 句话，配一张现有背景或人物立绘做底图，淡入淡出，点击翻页。最后一张接"今天"，直接进序章。

**数据**：`ChapterDef.recap = [{ title, text, image?, speaker? }]`。从章节选择进入、不经过前章时，同样会播，所以每章自给自足。

**写作纪律**：
- 只写**正史**（案一 TRUE END 的世界状态），不管玩家实际打出哪个结局，用叙述口吻，不写"你做了什么选择"。
- **不出现任何指向邵晓阳的暗示**（R02、R11）：他在案一只是"帮忙解释过的外包对接人"，提要里干脆不提。
- 黎默的动机写成他自己的说法："他说，是为了周屿。"（本质是贪，见 01d；提要里不下结论。）
- 林一程是平民，不称"林警官"。
